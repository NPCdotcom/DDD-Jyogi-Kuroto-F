## 3. C-3 報酬ポップアップ中の戦闘進行 [確認済み + 設計]

**事実**:
- `DungeonScreen.render` (200-221 行) は `statusPanelOpen` の時だけ `updateState` を止め、`eliteReward.isActive()` では止めない。
- `updateState` の PLAYER_TURN 分岐では、マウス方向入力だけを報酬中に抑止しており (262 行)、`playerInputs.poll` (数字・ENTER・WASD) は動き続ける。ENEMY_TURN 分岐では `enemyStepTimer += delta` (281 行) と敵ステップ (最大 10 回/フレーム) が続く。
- Elite は罠でも倒れ、`EliteDefeated` が出る (`TurnEngineHelpers.java:150-152`)。**敵ターン中にも報酬ポップアップが開く**。
- `EliteRewardOrchestrator.triggerOnEliteDefeat` (58-62 行) は表示中の 2 回目の呼び出しを無視する。同時に 2 体の Elite を倒すと、2 体目の報酬は出ない [確認済み: 静的]。1 体ごとに報酬を出すべきかは仕様が明記していない [要仕様判断]。

**仕様案**:
1. 報酬が表示されている間は `updateState` を呼ばない。プレイヤー入力・敵ステップ・`enemyStepTimer` の加算をすべて止める。`processNewEvents` (発生済みイベントの処理)、`effects.advanceEffects` (見た目の演出のみ)、`eliteReward.handleInput` だけを動かす。
2. ポップアップを開く時と閉じる時に `playerInputs.reset()` を呼び、カード選択を解除する。
3. 時間の扱い: 表示中は敵ターンのタイマーを加算しない。閉じた直後のフレームでは、そのフレームの delta だけを使い、溜まった時間をまとめて消化しない。
4. **開いたフレームと閉じたフレームの入力境界** (Critic v2 M09): 1 フレームは `updateState → processNewEvents (ここで報酬が開く) → eliteReward.handleInput` の順に進む (`DungeonScreen.java:204-207`)。このため、報酬が開いたフレームで押された数字キーが、一度も描画されないうちに報酬の選択に使われうる。`openedThisFrame` で開いたフレームの報酬入力を無効にし、閉じたフレームの入力もゲーム側へ流さない。`PlayerInputs.reset()` は選択状態を消すだけで、LibGDX の justPressed を消費しないことに注意する。
5. テスト: フレーム進行の判定を純関数 (状態 → {updateState, events, effects, rewardInput} の可否) に切り出す。さらに偽の Input を使い、呼び出し順まで含めて接続したテストで次を固定する。(a) 表示中の N フレームで敵ステップ 0 回・タイマー不変。(b) 閉じた直後の 1 フレームのステップ数が、同じ delta の通常フレームを超えない。(c) 同じフレームの数字キーが手札選択と報酬選択の二重に使われない。(d) 敵ターン中に罠で Elite を倒した時は、開く → 初回描画 → 次フレームで選択、の順になる。
6. 未決事項: 同時撃破時の報酬の数 (キュー化するか、1 回とするか)。

## 4. C-4a 保存失敗時の UI 契約 [確認済み + 設計]

**事実**:
- SAVE_FAILED: ENTER かクリックで `onRunEnded()` を再実行する (`GameOverScreen.java:116-120`)。
- INVALID_STATE: 何もしない (121-123 行)。
- 表示は状態によらず「持ち帰ったソウル: N」と「ENTER でソウルツリーへ」(`Strings.java:46-47`)。失敗時の N は、ラン開始時に 0 にした `progress.playerSoul` なので **0 と表示される** (`DddGame.java:429`、`GameOverScreen.java:54`)。
- `DddGame.dispose` は保存処理を持たない (785-791 行)。アプリ終了ではデータを書き込まない。

**契約案** (状態遷移と保存の規則は変えない。60ac172 の fail-closed を維持):

| 状態 | 見出し・本文 | 操作案内 | ENTER/クリック | ESC | 表示しないもの |
|---|---|---|---|---|---|
| SETTLED | 既存の見出し + 「持ち帰ったソウル (合計) T」 (今回の増減の表示は任意。精算前後の値を返す小変更が必要) | ソウルツリーへ | ツリーへ (既存) | なし | — |
| ALREADY_SETTLED | 「このランは精算済みです」 + 合計 T | ソウルツリーへ | ツリーへ (既存) | なし | 増減 |
| SAVE_FAILED | 「保存に失敗しました。まだ記録されていません」 + 空き容量・権限の確認依頼。再開できる Checkpoint の有無 (`RunLifecycle.canContinue()`) で文を出し分ける | 「ENTER: 再試行」「ESC: 保存せずに終了」 | 再試行 (既存) | アプリ終了 (保存なし) | ソウル 0 の表示、「ソウルツリーへ」 |
| INVALID_STATE | 「データの整合性エラーのため精算を中止しました。保存データは変更していません」 | 「ESC: 終了」 | 何もしない (既存) | アプリ終了 (保存なし) | ソウル数、「ソウルツリーへ」 |

テスト: `(RunEndResult, cleared, soulTotal, canResume)` から表示文と可能な操作を返す純関数を、4 状態 × クリア有無で全通り固定する。ESC での終了は保存を伴わないことを `dispose` の経路で確認する。
